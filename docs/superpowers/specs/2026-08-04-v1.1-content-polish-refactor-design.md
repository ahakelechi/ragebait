# Rage Quest v1.1: Second Level, Polish Pass, File Split, Leaderboard Rank, Settings

## Goal

Grow Rage Quest from a one-level joke platformer into a two-level one, with a real
(but scoped) juice pass, a maintainable file layout, a leaderboard that tells you
your rank even when you don't crack the top 10, and a settings panel covering
display, audio, controls, and accessibility. All still zero-build-step static files.

## 1. File split

Current single `index.html` (~1000 lines after the responsive/leaderboard work) splits into:

- `index.html` — markup skeleton, `<link>`/`<script src>` tags, and the Firebase
  bootstrap (config + `submit`/`top10`/`rank` helpers on `window.__scores`) inline.
- `style.css` — all CSS, unchanged content, just moved.
- `levels.js` — the `rect()` helper and a `LEVELS` array: `[{ width, solids }, ...]`
  for level 1 and level 2 (`groundY` stays the single shared constant it is today,
  not per-level — see below). Loaded as a plain classic script before `game.js`, so
  it just needs to define a global `LEVELS` — no export mechanism needed.
- `settings.js` — default settings object, `THEMES` presets, and localStorage
  load/save helpers. Loaded before `game.js`, defines global `Settings` (current
  values, already merged with anything saved) and `THEMES`.
- `game.js` — everything else (physics, input, camera, rendering, particles, sfx,
  leaderboard-panel UI, settings-panel UI). Reads `window.LEVELS`/`window.Settings`
  at startup.

**Why Firebase bootstrap stays inline:** it's the only `type="module"` script, and
Chrome/Firefox block loading an *external* module file over `file://` (cross-origin
restriction), which would break "just open index.html" for local testing — the CDN
`import` targets are remote HTTPS and unaffected either way. Keeping this one ~30-line
config-and-glue block inline avoids that regression; everything else is a classic
script/stylesheet, which loads fine over `file://`.

## 2. Second level + transition

- `LEVELS = [level1, level2]`. Each entry has its own `width` and `solids` array;
  `groundY` stays the shared constant (240) for both — only obstacle layout changes,
  not the ground-rendering assumptions baked into `drawMountainRow`/`drawCastle`.
- New state: `currentLevelIndex` (0-based). `solids`, `LEVEL_WIDTH` become references
  to `LEVELS[currentLevelIndex]` rather than top-level constants.
- Checkpoints, `checkpointX`/`checkpointName`, and `vanished` (fake/crumble tracking)
  are scoped to the current level — advancing to level 2 resets them for level 2's
  own checkpoints; dying in level 2 never routes back through level 1.
- `elapsed`/`attempts` are **not** reset on level transition — one continuous timer
  and attempt counter for the whole run, since the leaderboard tracks total time to
  finish both levels.
- Flag handling: `s.type === 'flag'` now checks `currentLevelIndex < LEVELS.length - 1`
  — not the last level → `nextLevel()` (banner + swap to next level's solids, reset
  player to its start x); last level → existing `win()` flow unchanged.
- HUD gains a fourth span: `LEVEL: 1/2` (updates on transition).

### New trap types (level 2)

| type | behavior |
|---|---|
| `moveplat` | Oscillates between two x/y points (sinusoidal, time-based). Player standing on it each frame gets carried by the platform's per-frame delta. |
| `crumble` | Solid on contact; after ~400ms of standing on it, shakes and vanishes (reuses the existing `vanished` set, same mechanism as `fake` but delayed instead of instant). |
| `togglespike` | Hazard that's only lethal during its "on" phase of a visible pulse cycle (~900ms on/900ms off, driven by `globalTime`); renders a faint outline during "off" as a telegraph. |
| `fakecheckpoint` | Visually identical to a checkpoint flag; touching it does nothing but show a one-off snarky banner line — no save, no death. |

## 3. Polish pass

- New sfx: `sfx.checkpoint()` (short double-blip, currently checkpoints are silent)
  and `sfx.levelComplete()` (a shorter 3-note fanfare, distinct from the 4-note `win`
  fanfare so the mid-game and final wins feel different).
- Level transition gets a ~120ms white `ctx.fillRect` flash (juice, matches the
  existing shake-on-impact language already in the game).
- Checkpoint save gets a small particle burst (reuses `spawnParticles`, same call
  shape already used elsewhere) instead of just a banner.

## 4. Leaderboard: own rank

- After a successful submit, if the new score isn't in the returned top-10 list,
  compute rank via Firestore's `getCountFromServer` aggregation query:
  `count(scores where time < myTime) + 1`. One extra read, no full-collection scan.
- Display: append "YOUR RANK: #N" below the top-10 list in the win banner. If the
  score *is* in the top 10, no extra line (rank is visually obvious from the list).
- Scope: this only applies to the post-submit win banner. The standalone "VIEW
  LEADERBOARD" button (available before you've won) still shows top-10 only — there's
  no "my time" to rank without a fresh submission.

## 5. Settings panel

A gear icon next to "VIEW LEADERBOARD" opens a persistent overlay (same show/close
pattern as the leaderboard overlay). All values persist to `localStorage` under one
`rq_settings` JSON blob and are re-applied on load.

### Display
- **Fullscreen** button: `document.documentElement.requestFullscreen()` /
  `document.exitFullscreen()` toggle. A `fullscreenchange` listener (alongside the
  existing `resize`/`orientationchange` ones) re-runs `fitToViewport()`.
- **Scale mode**: `fit` (current behavior, non-integer scale allowed, fills the most
  screen space) vs `pixel-perfect` (`scale = Math.max(1, Math.floor(scale))`, crisper
  pixel art, more letterboxing). Read by `fitToViewport()`.

### Audio
- **Volume slider** (0-100): stored as `Settings.volume` (0-1 internally). `beep()`
  multiplies its `vol` argument by `Settings.volume` before setting `g.gain.value`.
  Volume 0 is equivalent to mute — no separate mute checkbox needed.

### Theme
- 3 presets (`Neon` — current look, `Toxic` — green/purple, `Mono` — high-contrast
  grayscale), each a full value-set for both the canvas `COL` object and a matching
  set of CSS custom properties (`--col-accent`, `--col-bg`, `--col-frame`, etc.).
  Existing hardcoded hex values in `style.css` get replaced with `var(--col-*)`
  referencing `:root` defaults (Neon's values), so today's look is unchanged until a
  different theme is picked. Selecting a theme reassigns `COL`'s fields in place
  (canvas picks it up next frame, already redraws every frame) and calls
  `document.documentElement.style.setProperty(...)` for each CSS variable.

### Controls: key rebinding
- Input moves from direct `keys['arrowleft']`-style checks to a logical-action layer:
  `Settings.keyBindings = { left: 'arrowleft', right: 'arrowright', jump: ' ', sprint:
  'shift', restart: 'r' }` (defaults keep today's primary keys; WASD stays as
  always-on secondary defaults alongside whatever's rebound, so rebinding never removes
  the WASD fallback, only changes the *primary* arrow-equivalent key).
  `update()` and the `R`-restart handler read `actions.left/right/jump/sprint/restart`
  (computed each frame from whichever physical keys are currently down, checked
  against `Settings.keyBindings`) instead of raw key names.
- Touch buttons already set logical concepts, not raw keys conceptually — they get
  updated to set `actions.*` flags directly so they keep working regardless of
  rebinding.
- Rebind UI: 5 rows (Left/Right/Jump/Sprint/Restart), each showing the current bound
  key and a "REBIND" button; clicking it listens for the next keydown and stores that
  key as the new binding for that action.

### Practice / assist mode
- Checkbox. While on: `die()` becomes non-punishing — shows a short "would've killed
  you" toast and immediately respawns at the current checkpoint, with **no** attempt
  increment and no freeze delay. Falling out of bounds still respawns the same way
  (this was never really "the trap," just leaving the play area).
- **Leaderboard rule:** a run where practice mode was ever turned on is marked
  `usedPractice = true` (persists until `restartLevel()`); the win banner still shows
  the "you made it" text but the name/submit form is replaced with "Practice-mode
  runs aren't eligible for the leaderboard." This prevents practice mode from being
  used to fake an eligible fast time.

## Error handling

Unchanged from the existing spec: any Firebase failure (init, read, write, the new
count query) degrades to "Leaderboard unavailable" text, never breaks gameplay.
New trap types fail closed like existing ones — e.g. if `moveplat` math ever produced
`NaN`, the player would just fall through (same as any other solid miscomputing),
no new failure mode introduced.

## Testing

Manual, as before: complete level 1 and confirm the transition banner, timer
continuity, and checkpoint reset; ride a `moveplat` across a gap; stand on a
`crumble` tile and confirm the delay before it gives way; dodge a `togglespike` on
its visible cycle; touch a `fakecheckpoint` and confirm no save occurs; finish level
2 and confirm the leaderboard submit + rank line for a deliberately slow run.
Additionally: toggle fullscreen and confirm re-scaling; toggle pixel-perfect scale
mode at a few viewport sizes; switch each theme and confirm both canvas and CSS
chrome update; rebind a key and confirm both keyboard and (where applicable) touch
input still work; enable practice mode, confirm death is non-punishing and the win
banner blocks leaderboard submission for that run.

## Out of scope

- Level select menu (auto-continue only, per your answer).
- Per-level leaderboards (one combined leaderboard for total time across both levels).
- Leaderboard visual redesign (medal icons etc.) — rank line only.
- Any further engine files split beyond `levels.js`/`settings.js`/`game.js` (no
  `player.js`/`render.js` separation — game.js stays one cohesive engine file,
  reasonable size for this scope).
- Full custom key-per-key rebinding of every possible key (only the 5 named actions,
  one primary key each; WASD stays as a permanent secondary fallback).
- Settings sync across devices/accounts — `localStorage` only, per-browser.
